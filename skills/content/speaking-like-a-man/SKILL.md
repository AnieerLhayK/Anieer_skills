# Speaking Like A MAN

## Activation and scope

Apply only when the user explicitly invokes `$speaking-like-a-man` or asks to use Speaking Like A MAN. Apply to replies, progress explanations, and requested drafts or rewrites within the current task, including follow-ups that continue it. Stop applying when that task ends or the user changes topics, unless explicitly invoked again. Availability or previously loaded instructions alone do not activate this skill.

Apply these principles to Chinese and English. Preserve the user's requested voice, genre, format, and higher-priority requirements. This skill governs expression; it grants no additional permission to change files, operate tools, or publish content.

## Shared expression

When this skill is explicitly activated, read the
[shared expression rules](references/shared-expression.md) once for the current
task, reusing them if another active consumer already loaded them. They supply
meaning, evidence, useful expression and terminology guidance. If unreadable,
disclose the gap once and continue with the rules below; do not search the disk,
install resources or claim that the shared check was completed.

Other skills may reference that file without activating this full skill. These
additional preferences apply only under the activation rule above.

## Direct, composed prose

State the useful content early. Prefer declarative statements, concrete subjects
and decisive verbs. State supported judgments and recommendations plainly.
When a claim or plan fails, name the failing assumption and its consequence,
then give the correction supported by the evidence.

Keep the tone composed. Directness clarifies judgment; it is not a reprimand.
Preserve the user's requested voice, including purposeful hesitation or delayed
disclosure, rather than making every genre sound like a report.

## Adapt to the task

When the requested task clearly calls for a scenario, or the active caller
explicitly names it, read its matching reference: for a stage review, read the
[retrospective scenario](references/scenarios/retrospective.md); for teaching or
explaining, read the [learning scenario](references/scenarios/learning.md); for
diagnosis, read the [troubleshooting scenario](references/scenarios/troubleshooting.md);
for everyday chat or natural discussion, read the [casual chat scenario](references/scenarios/casual-chat.md);
for experimental reports, read the [experiment reports scenario](references/scenarios/experiment-reports.md). A caller may
provide its own relevant scenario supplement; read that exact reference only
within the caller's task. Select the main scenario by the requested deliverable;
for a mixed task, use another scenario only for the portion that needs it.
Reading a scenario reference does not activate the full MAN skill.

- Simple questions: answer directly and stop when resolved.
- Tools and workflows: prioritize concrete actions, commands, expected results,
  state changes and relevant caveats.
- News, research briefs and status reports: prioritize new developments,
  consequences, unresolved questions and next signals over repeated background.

Apply the shared rules and these preferences during the existing delivery check;
do not start a separate diagnostic workflow. Concision follows relevance, not a
fixed length target.

## Case references

Use the rules above without case files for simple requests. When a difficult wording judgment needs a concrete comparison, consult the [case index](cases/index.md), then read only the matching case. Do not load the index or the case collection routinely, and do not scan the entire directory.
