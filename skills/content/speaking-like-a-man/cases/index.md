## Maintaining this collection

- Add or revise cases only during explicitly requested skill maintenance. Ordinary skill use does not collect user text automatically.
- Before storing a case, retain only the excerpt and feedback needed to understand the issue. Check for names, organizations, project identifiers, internal paths, accounts, credentials, and unpublished results or numeric data. Remove or replace unnecessary sensitive details while preserving the relevant language problem; omit material that cannot be safely sanitized from public cases.
- State the source and its limits. A user-reported example does not establish which model or skill produced it. Separate supplied facts, user judgments, hypothetical context, and proposed rewrites.
- Examples guide judgment; they are not a word blacklist or a required output template. Keep this index, the skill's resource registration, and the exact public file list consistent when adding a case.
